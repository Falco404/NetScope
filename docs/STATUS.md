An IP-keyed row with no MAC (or the same MAC) re-keys to the MAC and returns `(merged, rekeys)`; `SQLiteStore.save_scan` migrates the row in the same transaction — `devices` parent first, then `device_ports`, `scan_devices` and `device_names` children, then deletes the old parent (order forced by `PRAGMA foreign_keys = ON`). A row that already carries a **different** MAC is treated as a different machine: the host becomes its own device and the stored MAC is never overwritten. 106 tests pass (5 new: 3 in `tests/test_device.py`, 2 in `tests/test_store.py`), ruff clean.
- **#36 Host header hardening** (PR #56, merged `865dca0` 2026-11-24): `build_app` installs Starlette's `TrustedHostMiddleware` as the outermost layer with `DEFAULT_ALLOWED_HOSTS = ("localhost", "127.0.0.1")` plus `extra_hosts`; `__main__.py` appends `NETSCOPE_HOST` (unless `0.0.0.0`/`127.0.0.1`) and the new comma-separated `NETSCOPE_ALLOWED_HOSTS`, and prints the trusted list at startup. A foreign `Host` now gets `400 Invalid host header` before any route runs — including `POST /api/scan`, so DNS rebinding cannot drive the scanner. Verified live: `localhost`/`127.0.0.1:8931` → 200, `evil.example.com`/`10.0.0.5` → 400; with `NETSCOPE_HOST=0.0.0.0 NETSCOPE_ALLOWED_HOSTS="192.168.0.14, atom.local"` those two → 200 and `evil.example.com` still 400. 111 tests pass (5 new in `tests/test_api.py`), ruff clean.
- **#37 SQLite threading (part 1 of 2)** (PR #57, merged `14d1139` 2026-11-24): the store keeps **one connection per thread** (`threading.local`; `store.conn` is a property) instead of one shared `check_same_thread=False` connection. A shared connection let a request thread read *and commit* the scan thread's open transaction — `set_device_name`'s `commit()` published a half-written `save_scan`, and readers could see a `scans` row with zero `scan_devices` rows. Each connection now sets `foreign_keys`, `journal_mode=WAL` and `busy_timeout` (per-connection pragmas); all writes go through `_write_txn()` (one lock + rollback on failure, so a failed write never leaves an open transaction behind). 114 tests pass (3 new in `tests/test_store.py`, all proven RED against the old code), ruff clean.
- **#37 progress reporting (part 2 of 2)** (PR #59, merged `7921d96` 2026-11-25): the scan engine now emits a **phase-aware** progress callback — `ProgressCallback = Callable[[str, HostResult | None], None]` with `PHASE_DISCOVERY`/`PHASE_SERVICES` and a `host is None` **phase-start sentinel** fired before each nmap pass — so the `-sn` discovery pass reports hosts as they are parsed instead of `hosts_found` jumping 0 → N at the very end. `ScanJob` gained in-process `phase` + `hosts_in_phase` (NOT persisted — transient telemetry; the final inventory is already in the store), and `/api/scan/status` now returns `phase` and `hosts_in_phase`. The UI status line reads e.g. `running — pass 1/2 (discovery) — 7 host(s) found`, and the bar is computed by a `barWidth()` helper (discovery fills the left half by elapsed-vs-per-pass-limit; services fills the right half by `hosts_in_phase / hosts_found`) — the old hardcoded `60%` is gone. 119 tests pass (5 new: 3 in `tests/test_scanner_engine.py`, 2 in `tests/test_api.py`, 1 guard in `tests/test_frontend_xss.py`, all proven RED against the old code), ruff clean.
- **#38 hostname ambiguity (`blocked.local`)** (PR #60, merged `45c6722` 2026-11-25): Falco's no-admin LAN scan showed **nine devices all named `blocked.local`** and a diff saying `blocked.local appeared` twice — nmap's reverse-DNS (PTR) name was identical for every IP because the LAN resolver answers every PTR query with the same name (a DNS sinkhole, most likely Atom's Pi-hole). The store now suppresses any hostname shared by 2+ devices at **read time** (`_suppress_ambiguous_hostnames`, applied in `load_devices` and `devices_in_scan`), so `display_name` falls through its existing chain to `Google device (192.168.0.5)` / bare IP, and diff lines become distinguishable. Nothing is rewritten in the DB (a later scan that resolves a unique name still wins via merge COALESCE), and a **unique** hostname still labels (`atom`/`apollo` regression guard). 124 tests pass (5 new: 3 in `tests/test_store.py`, 2 in `tests/test_api.py`, all proven RED against the old code), ruff clean.
- **#38 `/api/diff` unknown scan ids** (PR #61, merged `9391bf1` 2026-11-25): asking for a scan id that does not exist used to answer `200` with three empty lists — `{'from_scan': 1, 'to_scan': 999, 'appeared': [], 'disappeared': [], 'changed': []}` — so a typo'd id silently reported "nothing changed"; with only `to_id` given it 404'd but blamed the comparison partner instead of the bad id. `SQLiteStore.scan_exists` (new) plus explicit-id checks in the route now return `404 unknown scan id: N`; the defaults (newest scan, previous same-target scan from #31) are untouched. 127 tests pass (3 new: 1 in `tests/test_store.py`, 2 in `tests/test_api.py`, all proven RED against the old code), ruff clean.
- **#38 vendor registry data** (PR #63, merged `7278b72` 2026-11-25): the offline OUI table used to ship `AA:BB:CC -> MicroStar Intl` — a prefix that exists only in our recorded fixtures, with a vendor name invented for it — so **any real device whose MAC starts with `AA:BB:CC` would have been labelled "MicroStar Intl device (ip)"**. Checking the rest of the table against the IEEE OUI registrations (mirrored by uic.io) found three more wrong labels: `00:0C:AC` is Citizen Watch Co., Ltd. (was Dell), `A4:50:55` is BUSWARE.DE (was Apple), `E0:37:BF` is WNC Corporation (was Microsoft), and `DC:A6:32` is Raspberry Pi **Trading** Ltd (was Foundation). `3C:07:59` (labelled Intel) has no registration in either source checked, so it is gone too. The table now ships only verified prefixes, each with provenance in a comment. The suite never caught this because every `MicroStar Intl` assertion read the fixtures' own `vendor=` attribute, not the registry. 141 tests pass (4 new in `tests/test_device.py`, all proven RED against the old table), ruff clean. The vendor strings were later aligned to nmap's own (`Citizen Watch`, `Raspberry Pi Trading`, `WNC`) in the loader PR below, so one device keeps one name whichever table answers. The other half of this item is done there too — no capture from Falco's machine was needed after all: nmap publishes the data file, and this repo now ships a byte-exact slice of it as a fixture.

- **#38 load nmap's own `nmap-mac-prefixes` file** (PR #64, merged `ef0faba` 2026-11-25): `netscope/vendor_registry.py` gained `load_mac_prefixes(path)`, `find_mac_prefixes_file()` (nmap's own search order: `$NMAPDIR`, then the directory holding the nmap executable — on Windows `C:\Program Files (x86)\Nmap`) and `load_default_mac_prefixes()`; `main()` calls it before the store exists and prints which registry is in effect (`Vendor registry: 52085 MAC prefixes from C:\Program Files (x86)\Nmap\nmap-mac-prefixes` vs `Vendor registry: 5 built-in prefixes (no nmap-mac-prefixes found — install nmap or set NMAPDIR)`). The built-in 5-entry table stays as the fallback for a container/CI/pip-only install with no nmap. **The lookup rule changed too, and that was the real bug**: nmap's file is not all 3-byte prefixes — 38,930 keys are 6 hex digits (MA-S), 6,262 are 7 (MA-M) and 6,893 are 9 (MA-L), and **411** of the 6-digit keys are also the first 6 digits of a longer registration, so the old fixed-3-octet match answered `Ieee Registration Authority` for `00:1B:C5:00:00:11` where the 9-digit `001BC5000 Converging Systems` is correct. Lookups now try the longest registered prefix first. Comment lines are not entries: the header's `# Nmap additions to this file:` / `# 525400, B0C420, DEADCA, 00FFD1, 080027,` would otherwise invent vendors for those five prefixes. Fixture `tests/fixtures/nmap-mac-prefixes-sample.txt` is a byte-exact slice of nmap master's file (52,091 lines, sha256 `ae8b132bb3471ea94055e111137f76e041f4a8f5df9799ac184cc1fbf23d508d`, captured 2026-11-25); every entry line was verified present verbatim upstream, and the fixture header records that provenance. 8 new tests in `tests/test_vendor_registry.py`, all proven RED against the old code; ruff clean.

- **#38 env-var validation** (PR #62, merged `4e29467` 2026-11-25): `NETSCOPE_PORT=8000abc` used to die with a bare `ValueError: invalid literal for int() with base 10: '8000abc'` traceback that never named the variable. `parse_port` / `parse_timeout` (new, in `netscope/__main__.py`) now reject bad values with a message naming the variable, the bad value and the expected shape, and `main()` turns that into `Bad configuration: NETSCOPE_PORT must be an integer port number (e.g. 8000), got '8000abc'` with exit 1 — no traceback.
